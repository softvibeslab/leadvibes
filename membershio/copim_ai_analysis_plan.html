Plan de Implementacion

Analisis IA en Cards COPIM dentro de ROVI

Objetivo: llevar a Asociaciones, Socios, Membresias y Eventos el mismo patron de valor que ya existe en Leads: detalle profundo, analisis con IA, lectura accionable y siguientes pasos claros.

Detalle por registro Boton Analizar con IA Respuesta persistida Bloques accionables Scripts o mensajes sugeridos
Patron actual valido Leads

Ya existe modal de detalle, tab de IA, endpoint de analisis y generacion de scripts.

Modulo 1 Asociaciones

Salud institucional, expansion, cobranza y activacion por capitulo.

Modulo 2 Socios

Activacion, completitud, riesgo de fuga, valor de directorio y credencial.

Modulo 3 y 4 Membresias + Eventos

Renovacion, cobranza, asistencia, ocupacion y follow-up.

1. Patron de referencia actual en Leads

Hoy el modulo de Leads ya resuelve la experiencia correcta y debe usarse como blueprint directo para COPIM.

  • El detalle vive dentro de un modal con tabs: informacion, actividades, analisis IA y script.
  • El analisis se ejecuta a demanda con un boton explicito: POST /api/leads/{lead_id}/analyze.
  • El resultado se guarda en el lead como ai_analysis y actualiza el score visible.
  • La salida no solo describe: tambien recomienda siguiente accion y puede generar script.

2. Regla de diseno para COPIM

El analisis IA no debe sentirse como dashboard aparte ni como juguete demo. Debe vivir en el flujo operativo donde ya se revisa cada registro.

  • Cada card mantiene su boton Ver detalle.
  • Dentro del detalle se agrega tab o bloque Analisis IA.
  • El boton Analizar con IA corre el endpoint de esa entidad.
  • El resultado se persiste en Mongo para no recalcular cada vez.
  • Se muestra fecha de ultimo analisis y nivel de frescura.

Arquitectura propuesta

Frontend

  • Reusar los detail sheets ya creados en COPIM.
  • Agregar tab Analisis IA por entidad.
  • Mostrar score principal, resumen ejecutivo, riesgos, oportunidades y siguientes acciones.
  • Agregar boton secundario para generar mensaje o script de seguimiento cuando aplique.

Backend

  • Agregar endpoints /analyze por entidad.
  • Agregar campo persistido ai_analysis.
  • Agregar ai_last_analyzed_at y score resumen.
  • Agregar funciones nuevas en backend/ai_service.py.

Datos

  • Usar el documento actual de la entidad mas sus datos relacionados.
  • Construir contexto enriquecido antes de mandar el prompt.
  • Evitar prompts genicos: cada entidad necesita schema y semantica propia.

Analisis IA para Asociaciones

Entrada minima al prompt: estado, ciudad, estatus, meta de socios, activos, pendientes, renovaciones, credenciales emitidas, miembros visibles, cobranza visible, eventos proximos, responsables y notas.

JSON recomendado

{ "association_health_score": 0, "risk_level": "bajo|medio|alto", "expansion_signal": "fuerte|moderado|debil", "executive_summary": "...", "key_strengths": ["..."], "critical_risks": ["..."], "operational_blockers": ["..."], "recommended_actions": ["..."], "presidency_message": "...", "operations_message": "..." }

UI recomendada

  • Score general arriba con badge de riesgo.
  • Resumen ejecutivo de 3 a 4 lineas.
  • Fortalezas y riesgos en dos columnas.
  • Acciones sugeridas para presidencia y para operacion.

Analisis IA para Socios

Entrada minima al prompt: estatus, tier, perfil, empresa, asociacion, visibilidad en directorio, credencial, saldo, membresias asociadas, fecha de alta, notas y completitud de perfil.

JSON recomendado

{ "member_activation_score": 0, "retention_risk": "bajo|medio|alto", "profile_gap_summary": "...", "value_realized": "alto|medio|bajo", "key_gaps": ["..."], "recommended_actions": ["..."], "credential_recommendation": "...", "outreach_message": "..." }

UI recomendada

  • Score de activacion y riesgo de retencion.
  • Lo que le falta para que el perfil quede util.
  • Si conviene credencial, directorio o renovacion primero.
  • Boton para generar mensaje de seguimiento listo para copiar.

Analisis IA para Membresias

Entrada minima al prompt: plan, precio, periodo, renovacion, estatus de pago, saldo, metodo de pago, factura, auto-renovacion, recordatorios, beneficios y notas.

JSON recomendado

{ "renewal_risk_score": 0, "collection_priority": "baja|media|alta|critica", "payment_context_summary": "...", "renewal_probability": 0, "key_blockers": ["..."], "recommended_actions": ["..."], "collection_message": "...", "upsell_signal": "si|no" }

UI recomendada

  • Semaforo de cobranza.
  • Probabilidad de renovacion y motivo.
  • Guion de cobro o seguimiento.
  • Indicador de si conviene upsell o si primero hay que regularizar.

Analisis IA para Eventos

Entrada minima al prompt: tipo, formato, estatus, speaker, fechas, capacidad, registros, check-ins, ocupacion, asistencia, visibilidad, sede y descripcion.

JSON recomendado

{ "event_momentum_score": 0, "attendance_risk": "bajo|medio|alto", "registration_health": "fuerte|moderada|debil", "event_summary": "...", "critical_signals": ["..."], "recommended_actions_pre_event": ["..."], "recommended_actions_post_event": ["..."], "followup_message": "..." }

UI recomendada

  • Lectura de momentum antes del evento.
  • Riesgo de baja asistencia.
  • Siguiente empuje sugerido: invitaciones, recordatorio, post evento.
  • Mensaje sugerido para convocatoria o follow-up.

Modelo tecnico recomendado

En vez de guardar la IA en otro collection separado, para esta fase conviene persistirla en el mismo documento de cada entidad, como ya se hace con ai_analysis en Leads.

{ "ai_analysis": { "entity_type": "association|member|membership|event", "version": "v1", "score": 78, "risk_level": "medio", "executive_summary": "...", "key_points": ["..."], "recommended_actions": ["..."], "suggested_message": "...", "raw": {...} }, "ai_last_analyzed_at": "2026-05-04T00:00:00Z" }

Si despues quieres historico, entonces si conviene agregar una coleccion tipo copim_ai_analysis_runs.

Criterios de aceptacion

  • Cada modulo COPIM tiene detalle con tab o bloque de IA.
  • El analisis corre desde el frontend y queda persistido.
  • El usuario puede volver a abrir el detalle y ver el ultimo analisis sin recalcular.
  • La IA siempre devuelve estructura consistente por entidad.
  • Si la IA falla, existe fallback legible y no se rompe la pantalla.
  • El analisis produce al menos una siguiente accion concreta.

Riesgos y decisiones

  • Riesgo: prompts demasiado genericos dan analisis blandos. Solucion: schema y contexto por entidad.
  • Riesgo: recalculo en cada apertura sube costo. Solucion: persistir resultado y refrescar bajo demanda.
  • Riesgo: si solo se muestra texto largo, pierde valor. Solucion: scores, bullets y acciones.
  • Decision recomendada: arrancar con analisis bajo demanda, no automatico.

Recomendacion final: no empieces por badges en las cards. Primero implementa el patron completo dentro del detalle, igual que en Leads. Cuando el analisis ya sea util y consistente, entonces si subimos una version resumida a la card: score, riesgo y fecha de ultimo analisis.
